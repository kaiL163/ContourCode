# КонтурКод — прототип платформы алгоритмических соревнований

## Текущее состояние backend

Backend и его интеграция находятся в разработке и **не реализуют весь набор сценариев ТЗ**. Интерфейс местами всё ещё содержит демонстрационные данные; регистрацию, результаты, парные режимы и проверку честности нельзя считать сквозными рабочими сценариями. Модуль JPlag не подключён к API. Проверка Judge0 и границы изоляции не подтверждены сквозными испытаниями, несмотря на наличие контейнеров.

Локальный предварительный запуск (Docker Desktop с Linux-контейнерами):

```sh
docker compose --env-file .env.example up -d --build
```

Интерфейс: http://localhost:8080/; проверка API: http://localhost:8080/api/health. Для входа в частичный прототип подготовлен локальный демонстрационный организатор `demo-organizer` с паролем `demo123`. Полноценные демонстрационные данные участников пока не гарантированы. Остановка: `docker compose --env-file .env.example down` (данные в volumes сохраняются).

**Только для локальной разработки:** конфигурационные файлы `.env.example` и `judge0.conf.example` содержат общедоступные демонстрационные значения и должны быть заменены на индивидуальные секреты перед любым использованием вне локальной машины. В текущем Compose `judge0.conf.example` смонтирован непосредственно в Judge0: при смене конфигурации необходимо согласовать значения с `.env.example` для его базы и Redis. Judge0 использует привилегированные контейнеры; это риск безопасности, и такой запуск нельзя считать безопасным для недоверенного кода без отдельной проверки и изоляции Linux-хоста. Не публикуйте этот прототип в интернет.

## Локальный frontend

Рабочий frontend находится в каталоге [frontend](frontend). Для запуска нужен Node.js 20.19+ или 22.12+.

```powershell
cd frontend
npm install
npm run dev
```

Vite выведет адрес локального приложения (по умолчанию `http://localhost:5173`). Для production-сборки выполните `npm run build`, для локального просмотра сборки — `npm run preview`.

Frontend использует локальные моковые данные и состояние вкладки. Вход, роль, регистрация, создание задач и контестов, проверка решений, дуэли, команда, таблица результатов и экран проверки прохождения работают как демонстрационные сценарии. Код решения не исполняется и не передаётся на сервер; статусы и обновления не синхронизируются между пользователями. Для реальной проверки нужны backend, хранилище и изолированный Judge0; для общих приглашений и реального времени — API и WebSocket.

Основной интерфейс бренда и entry point frontend называется **КонтурКод**. Ранее созданные документы и Figma-макеты могут содержать рабочее название «Алгосход» и визуальные референсы, составленные до frontend.

«КонтурКод» — название frontend. [DESIGN.md](DESIGN.md) и Figma-макеты создавались раньше и местами используют рабочее название «Алгосход»; их сценарии используются как ориентиры, а интерфейс реализован в самостоятельном визуальном стиле.

[Макет в Figma](https://www.figma.com/design/BmJkc1YHf27XTnJItGH8gL?node-id=8-321): 14 редактируемых экранов и состояний. Это дизайн, а не работающий прототип приложения. Повторная визуальная проверка после исправления компоновки и настройка кликабельных переходов остались незавершёнными из-за лимита Figma MCP; подробности и схема завершения — в DESIGN.md.

## О проекте

Frontend-прототип веб-платформы для соревнований по программированию: обычных контестов, дуэлей 1 на 1 и командных соревнований. Организатор получает демонстрационный интерфейс проверки честности результатов.

Источник требований: «ТЗ.pdf», 8 страниц, кейсовое задание хакатона. Ссылки на страницы далее относятся к этому документу.

## Цель

Дать возможность провести соревнование по программированию, в том числе в командном формате, и проверить честность его результатов в одной платформе. Результат проекта — работающий проверяемый прототип и обоснованная концепция продукта (ТЗ, с. 2).

## Основные возможности по ТЗ

- Две роли: участник и организатор. Регистрацию и вход разрешено имитировать.
- Задачи с условием, ограничениями времени и памяти, набором тестов.
- Отправка решений хотя бы на одном языке программирования; автоматическая проверка в изолированной среде с лимитами.
- Вердикты как минимум `OK / WA / TLE / RE / CE`.
- Обычный контест: создание организатором, выбор задач, времени начала и длительности; регистрация участников и таблица результатов.
- Дуэль 1 на 1: одинаковые задачи для двух участников, прогресс в реальном времени, определение победителя.
- Команда из двух человек: совместное решение общего набора задач, результат засчитывается команде.
- Подбор соперника или напарника хотя бы по ссылке-приглашению; отображение хода обоих парных режимов в реальном времени.
- Проверка честности организатором после соревнования; конкретный способ выбирает команда-разработчик.

Подробности и критерии готовности: [TASK.md](TASK.md).

## Границы проекта

ТЗ не предполагает полноценного аналога Codeforces с многолетним архивом и рейтингом, LMS или прокторинговой системы общего назначения (с. 2). Дополнительные функции допускаются ТЗ, но в этот комплект требований не добавлены.

## Стек

ТЗ не ограничивает стек и разрешает готовые библиотеки и сервисы, включая проверку решений (с. 6).

**Рекомендация, не требование ТЗ:** TypeScript и React с Vite для интерфейса; Python и FastAPI для серверной части; PostgreSQL для хранения данных; Judge0 CE для изолированной проверки; Docker Compose для воспроизводимого запуска. Обоснование и ссылки на документацию: [TECH_STACK.md](TECH_STACK.md).

## Запуск

Frontend локально запускается командами выше. Backend не входит в текущий этап; реальный сервер, изоляция исполнения кода и синхронизация между участниками не реализованы. Для демонстрации используются встроенные моковые данные и локальное состояние приложения.
